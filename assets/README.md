# assets/

Исходники визуальных ассетов. Правило зависит от ассета: у баннера для README
источник — SVG, и правится он; у иконки приложения источник — растр, и правится
он.

## Иконка приложения

Исходник — `assets/icon.jpg` (1024×1024, без альфы). Готовые файлы лежат в
репозитории и правятся только вместе с исходником:

- `build/icon.png` — 1024×1024, белый фон снят, 32 бита с альфой; берёт окно в
  dev-режиме;
- `build/icon.ico` — размеры 16, 24, 32, 48, 64, 128, 256; берёт сборка
  (`win.icon` в `package.json`).

Пересобирать конвейером в репозитории нечего: файлы коммитятся, а правка
исходника — ручная работа (снять белый фон, положить PNG и собрать `.ico` из
семи размеров, положить рядом). Проверять результат нужно глазами на фоне,
отличном от белого: белые углы квадрата должны быть прозрачными, а не белыми.

## readme/hero.svg → шапка README

Статичный баннер 1200×420 под заголовком в `README.md` (строка-картинка
markdown). Собран из данных самого проекта, а не из выдумки: палитра и радиусы
из `src/renderer/index.css`, иконки полок скопированы из
`src/renderer/CategoryIcon.tsx` (24 юнита, масштаб 1.3333 → 32px, как `h-8 w-8`
в приложении), числа сверены с `src/shared/catalog.ts` и `src/shared/taxonomy.ts`
(3 сети, 15 городов, 16 полок, реальные коды `35XY · 303857 · 4161`).

## Что проверяется

Баннер: файл не читают ни `tsc`, ни `vite build`, ни `electron-builder` — молчал
любой прогон, поэтому проверка живёт в `npm run test:icons` (входит в
`npm test`), секция 7 в `scripts/test-icons.ts`:

- структура: каждый тег строго `<тег attr="value" …>` (именно эта проверка
  поймала `scale(1.3333)""`, из-за которого standalone-SVG не парсился и
  GitHub отдавал битую шапку вместо первого экрана). Сверх этого — `&` в любом
  виде (сущности в файле не используются) и `--` вне комментария: второе по
  XML формально допустимо, но ловит автора, который правит файл как HTML;
- позиция: 4 иконки на `x=640`, оптический центр = `translate_y + центр_bbox ×
  scale` с допуском 0.5 от `baseline − 0.35·fontsize` (реальные расхождения
  ≤ 0.4; привязка к id полок `dairy/bakery/meat/vegetables`, а не к номеру —
  иначе вставка категории в `CategoryIcon.tsx` переспарила бы строки);
- контраст: у каждого `<text>` (без `fill` или `x` — падение, а не пропуск)
  цвет читается из файла, поверхность — по колонке (`x ≥ 612` — белая карточка,
  левее кремовый фон), порог 3:1 для крупного текста (≥24px либо ≥18.66px жирный)
  и 4.5:1 иначе;

Растр не делается: в README лежит сам SVG. Превью — снять в браузере; важно
открывать `file://` самим SVG, а не вставлять инлайном в HTML: lenient-парсер
HTML проглатывает битый XML, и дефект не виден.

## Правки после создания

Девять дефектов, найденных при проверке, все закрыты:

- **P0** — четыре лишние кавычки `scale(1.3333)""` делали файл невалидным XML;
- зачёркнутая старая цена была `#94a3b8` (2.56:1 на белом) → `#475569`, как
  `text-muted` в приложении;
- пилюли сетей были `#ecfdf5` на белой карточке (1.03:1, скруглений не видно) →
  `fill="#ffffff" stroke="#d8efe8"`, как `border-line bg-card`;
- иконки висели на ~12px выше оптического центра строки → `translate` подобран
  под визуальный центр текста, сетка шага 54 (129/183/237/291);
- у моркови контур рисовался дважды (SOFT уже несёт `fill` + `stroke`);
- бейдж «−14%» удалён: в приложении его нет, а белым по `#059669` он давал
  3.77:1; промо-строка повторяет `App.tsx:1839-1844` — подпись сети, старая
  цена зачёркнутым приглушённым, новая жирными чернилами;
- названия полок «Молочное» и «Овощи и фрукты» не существовали в таксономии →
  «Молочное и яйца» и «Овощи» (`taxonomy.ts`);
- строка кодов `35XY · 303857 · 4161` стояла под шапкой «Новосибирск» →
  `Москва: …` (это московская тройка);
- добавлены `width`/`height`, чтобы рендер не зависел от `aspect-ratio`, и
  поправлен вертикальный ритм левой колонки (низ был на 19px ниже карточки).
